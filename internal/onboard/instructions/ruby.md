Set up Ruby Test Optimization for the repository's existing __FRAMEWORK__ command.

1. Keep the existing Gemfile, lockfile, Ruby versions, bundle exec/binstub/Rake/Rails entry points, test arguments, reporters, coverage settings and required application setup. Install the project's normal dependencies first. In a mixed RSpec/Minitest repository, scope this change to __FRAMEWORK__; validate the other framework separately.
2. Ask a human to connect Datadog and configure the CI secret if needed. Add `datadog/test-visibility-github-action@v3` after `ruby/setup-ruby` and bundle setup, before each selected test step. Set `languages: ruby`, `api_key: ${{ secrets.DD_API_KEY }}`, and an exact `ruby-tracer-version` compatible with every selected Ruby. Preserve the original matrix. The action installs datadog-ci and exports `RUBYOPT=-rbundler/setup -rdatadog/ci/auto_instrument`; merge existing Ruby options instead of overwriting them. Keep custom tracer installation paths visible for separate review.
3. Run `ddtest testdrive --framework __FRAMEWORK__ --all --check-only --yes`. This inventories explicit GitHub Actions commands and checks the installed bundle without installing gems or executing tests. CI checks require exact Ruby and tracer versions; floating versions, unresolved conditions, custom installs and unrecognized wrappers remain inconclusive. A compatible static check does not prove remote CI execution.
4. Run `ddtest testdrive --framework __FRAMEWORK__ --all --tracer-version <resolved-release> --yes` after final setup edits. Use `--command '<existing test command>'` instead of `--all` to validate one prepared local configuration. Existing bundled datadog-ci is reused, so verify the reported actual release. A missing tracer is installed only in a disposable repository copy; the customer's Gemfile and lockfile are preserved.
5. Inspect native baseline/reporting-only comparisons and each controlled feature result: retries, early flake detection, Test Impact Analysis skipping, quarantine, disabled tests and attempt-to-fix. Check that reporting-only coverage names existing application source files; test-file coverage alone is insufficient. The companion observer retains existing reporters. Probes use the selected command and its loaded configuration; if filters, wrappers or custom reporters prevent collecting controls, the feature stays unvalidated. Existing failures may match across both runs. Missing native results or telemetry cannot count as success.
6. Keep `.testoptimization/report.html` and `.testoptimization/testdrive.json`, including on failure. Temporary copies, observers and probes are removed. Run full validation again after edits; a later check-only keeps older execution as historical evidence. Copy testdrive's final response block and absolute report links. Report unresolved checks and unexecuted configurations explicitly. No Datadog credentials are needed for these local checks; actual CI execution and Datadog backend processing remain untested.
