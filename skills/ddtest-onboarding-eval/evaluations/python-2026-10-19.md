## Findings and fixes

1. Initial Click/MarkupSafe onboarding could not discover standard
   `uv run --locked --no-default-groups --group dev ...` test jobs. Discovery and
   interpreter selection now preserve these flags; regression tests cover them.
2. Initial ItsDangerous/Codex added the action without forwarding its environment
   through tox. Python guidance now explicitly requires extending `pass_env`
   with `DD_*`, `PYTHONPATH` and `PYTEST_ADDOPTS`, retaining existing entries.
   All six final agents added the forwarding.
3. Initial MarkupSafe feature controls were inconclusive because autouse
   parametrization yielded two probes. Validation now inventories every variant
   and exercises each independently in the original fixture configuration.
   Both real agent runs verify the fix; EFD's separate tracer limitation remains visible.

All final product reports retain INCOMPLETE for unresolved dynamic tox/GitHub
matrix conditions. No trial validates the complete CI matrix or real Datadog
processing. Independent static review also found that Codex's final edits still
target unsupported PyPy/free-threaded entries in one or more jobs. Claude's final
edits guard unsupported entries while preserving their ordinary test execution.
These are separate agent configuration findings, not six successful onboardings.
[Release metadata](https://pypi.org/pypi/ddtrace/4.16.0/json) was checked independently:
Python requirement `<3.15,>=3.9`; no PyPy or CPython free-threaded wheels.

The final labeled verdicts/counts/report links match JSON for all agents.
Click/Codex additionally described its remaining blockers as only static-analysis
limits; independent CI review does not support that narrower claim.
All ddtest session cleanup checks passed. Five final agents left ordinary ignored
pytest/Python caches; ItsDangerous/Codex cleaned those artifacts. Evaluator
teardown removes owned trial roots separately after preserving evidence.

HTML reports were retained, parsed, served successfully over loopback, and checked
for real-suite content, absence of synthetic probes, and valid sibling JSON links.
Visual browser verification was unavailable because browser access was not available.

## Reproduce

Build this branch, then run from the ddtest checkout with authenticated CLIs,
Python 3.12 and network access. Follow the evaluator skill's account/connector
isolation prerequisites. Repeat this command for each project SHA above and both
`--agent codex` / `--agent claude`, using a new output directory each time:

```sh
python3 skills/ddtest-onboarding-eval/scripts/run_eval.py \
  --repo https://github.com/pallets/itsdangerous.git \
  --ref 672971d66a2ef9f85151e53283113f33d642dabd \
  --ddtest /absolute/path/to/this-branch/ddtest \
  --agent codex --framework pytest --python /absolute/path/to/python3.12 \
  --isolate-agent-config \
  --setup-command 'python -m pip install --disable-pip-version-check -e . pytest==8.4.2 freezegun==1.5.5' \
  --output /absolute/path/to/new-evidence-directory --timeout 1800
```

For Click and MarkupSafe omit freezegun. Inspect the emitted command/run evidence;
CLI exit zero is not an onboarding success criterion. Each trial retains its
manifest, public activity (no model reasoning), patch/status, final answer,
assessment, HTML and compact JSON outside the disposable clone. The local evidence
bundle for this evaluation is `/tmp/ddtest-python-e2e-192` (not required by the runner).

## Subsequent PR review fixes

The [Codex review](https://github.com/DataDog/ddtest/pull/192#pullrequestreview-5571397344)
and [Bits review](https://github.com/DataDog/ddtest/pull/192#pullrequestreview-5571497917)
identified nine reproducible configuration issues. Corrections preserve versioned
interpreters and application `DD_*` variables, discard inherited default-runtime
failures before each command's preflight, retain selected environments during
tracer verification, expand matrix commands before candidate filtering, and scope
matrix preservation to pytest jobs. CI checks now apply environment precedence
and reject disabled tracing or disabled plugin autoload without explicit loading.

These corrections were verified after the agent trials above; their original
results have not been relabeled as runs of the newer binary. Focused regressions
failed before the corrections and passed afterward. A separate real pytest 8.4.2 /
ddtrace 4.16.0 fixture validated `python3.12 -m pytest` and
`uv run --no-sync python -m pytest` selected through a command matrix. Its default
uv environment had no pytest, while CI selected a prepared environment through
`UV_PROJECT_ENVIRONMENT`. Application environment assertions, parent/step options,
explicit plugin loading and an unrelated conditional docs job were retained.
Both paired configurations passed, with 12/12 feature checks and a COMPLETE LOCALLY
verdict. Check-only variants with `--no-ddtrace` or missing explicit plugin loading
both returned INCOMPLETE with incompatible CI findings. Full `make test` (including
real pytest integration) and pinned `make lint` passed. This fixture does not
change MarkupSafe's parametrized-test EFD limitation or establish remote CI coverage.
